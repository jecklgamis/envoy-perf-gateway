   to push backends and fault injection.

3. gatewayctl fault abort/delay/reset distribute through the same
   pipeline as backends (values.yaml -> config server/S3 -> every
   replica's fetcher), so they apply consistently across
   gateway.replicaCount replicas and survive pod restarts. Expect the
   change to take effect on the fetcher's next poll
   (CONFIG_POLL_INTERVAL_SECONDS, 15s by default), not instantly.

   For a sub-second, single-pod override instead (in-memory only, lost on
   that pod's next restart), hit its admin API directly - not exposed as
   a Service by this chart, so port-forward the pod itself:

   kubectl port-forward -n {{ .Release.Namespace }} <gateway-pod-name> 9901:{{ .Values.gateway.service.adminPort }}
   curl -X POST "http://localhost:9901/runtime_modify?fault.http.abort.abort_percent.httpbin=100&fault.http.abort.http_status.httpbin=503"
